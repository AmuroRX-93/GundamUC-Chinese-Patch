# 高达 UC：上一版用户更新说明

> 2026.09.19-delta.3-rc.1 正式发行更新说明（沿用 RC1 构建）。支持旧版指纹：2026.09.14-delta.1、2026.09.14-delta.2。1.01 已实际载入升级程序，用户确认进入主菜单；全部影片、DLC 任务和长时间稳定性未完成验收。

## 1. 先分清三个版本号

| 名称 | 含义 | 本次处理方式 |
| --- | --- | --- |
| 游戏本体 01.00 | 光盘游戏的基础版本 | 保留支持 |
| 官方升级 01.01 | 安装在游戏数据目录中的升级覆盖层 | 对已核对指纹的版本增加支持 |
| 汉化发行版本 | 如上一版 `2026.09.14-delta.2` | 与游戏版本号分开记录 |

口头说的“1.0 / 1.1”在本说明中对应 **01.00 / 01.01**。仅凭压缩包名称无法确定版本。

游戏编号必须是 **BLJS10154（日版高达 UC）**。BLJS10050 是另一款游戏；不要混用其补丁、DLC 或配置。

安装 01.01 后，光盘目录中的 PARAM.SFO 仍可能显示 01.00：升级版本位于模拟器的 `dev_hdd0/game/BLJS10154` 内。两处版本不同不一定是错误。

**汉化差分不会把官方升级文件变出来。** 想从 01.00 升至 01.01，需要先准备并正确安装对应升级；新版整合包则应按包内版本清单提供已经整理好的匹配资源。

## 2. 你该选择哪条更新路线

| 你现在持有的内容 | 操作路线 | 是否重下完整游戏 |
| --- | --- | --- |
| 上一版汉化整合包，已能运行 | 下载新版差分，先做只读检查，通过后增量更新 | 识别为支持的旧版时不需要 |
| 原版游戏＋上一版差分汉化 | 同上，指定原来的游戏目录；有 DLC 时同时指定 DLC 目录 | 检查通过时不需要 |
| 干净原版 01.00 | 安装新版差分；可以继续保持 01.00 | 不需要 |
| 干净原版＋01.01＋DLC | 指定本体和对应的游戏数据目录，通过版本检查后安装 | 不需要 |
| 已下载新版整合包 | 解压到新的独立目录，按整合包说明导入 | 不再重复运行差分 |
| 来源不明的旧汉化、混装补丁或修改版 | 先只读检查；不通过则保留旧目录，换用支持的干净来源 | 不能保证直接升级 |

上一版升级支持必须以最终发布清单列出的版本为准，不能把“看起来是旧版”当作指纹相同。安装器拒绝未知资源时，不要改清单、跳过校验或改版本号强装。

## 3. 更新前准备

1. 正常保存游戏并完全退出 RPCS3。不要在运行中更新，也不要同时运行两个安装器。
2. 完整解压差分包到一个普通文件夹，不要从压缩软件内部直接运行脚本。
3. 确认游戏目录中存在 `PS3_GAME/PARAM.SFO`。选择这一层的外层目录作为 `--game`。
4. 如果已经安装升级或 DLC，找到**当前模拟器实际使用**的 `dev_hdd0/game/BLJS10154`，作为 `--dlc`。移动过数据盘或使用便携版时，不要照抄他人的路径。
5. 备份自己的存档及重要模拟器配置。补丁处理游戏资源，不主动处理个人存档；备份可保护你免于选错目录或后续人工操作的损失。
6. 留足暂存和回退空间。所需空间取决于本次修改的资源大小，不能只看差分 ZIP 大小。安装器会检查空间。
7. 保留上一版压缩包，直到新版本实际进入游戏、声音与显示正常。

不要删除整个 `dev_hdd0`。`dev_hdd0/game/BLJS10154` 是游戏数据目录，不等于整个用户数据目录；个人存档通常另存于 `dev_hdd0/home/<用户编号>/savedata`。本补丁不要求你删除存档、格式化磁盘或重新安装模拟器。

## 4. 目录长什么样

本体目录示例：

```text
GundamUC/
  PS3_DISC.SFB
  PS3_GAME/
    PARAM.SFO
    USRDIR/
      EBOOT.BIN
      LaunchData.bnd
      GameData.bhd
      GameData.bdt
      sound/
```

已有升级／DLC 的目录示例：

```text
RPCS3 实际数据目录/
  dev_hdd0/
    game/
      BLJS10154/
        PARAM.SFO
        USRDIR/
          EBOOT.BIN       01.01 升级层可能包含此文件
          mission/
          system/
          sound/
```

不要将 `PS3_GAME` 整个放进 `dev_hdd0/game/BLJS10154`，也不要多套一层 `BLJS10154/BLJS10154`。

## 5. Windows：先检查，再安装

安装 Python 3.10 或以上。打开 PowerShell，用 `cd` 进入解压后的差分包目录。下面路径只是示例，应替换成自己的实际路径，并保留引号。

只检查本体：

```powershell
py -3 .\install.py --game "D:\Games\GundamUC" --check-only
```

本体和已经安装的升级／DLC 一起检查：

```powershell
py -3 .\install.py --game "D:\Games\GundamUC" --dlc "D:\RPCS3\dev_hdd0\game\BLJS10154" --check-only
```

检查通过后，保持路径不变，去掉 `--check-only` 进行安装：

```powershell
py -3 .\install.py --game "D:\Games\GundamUC" --dlc "D:\RPCS3\dev_hdd0\game\BLJS10154"
```

没有升级／DLC 时省略 `--dlc` 和它后面的路径；不要随便指向一个空目录。若系统只有 `python` 命令，可先运行 `python --version` 核对版本，再替换命令开头的 `py -3`。

## 6. macOS / Linux：先检查，再安装

在终端进入差分包解压目录。`/路径/` 是占位说明，不是要原样输入的路径。

```sh
python3 ./install.py --game "/路径/GundamUC" --check-only
```

有升级／DLC：

```sh
python3 ./install.py --game "/路径/GundamUC" --dlc "/实际RPCS3数据目录/dev_hdd0/game/BLJS10154" --check-only
```

检查通过后安装：

```sh
python3 ./install.py --game "/路径/GundamUC" --dlc "/实际RPCS3数据目录/dev_hdd0/game/BLJS10154"
```

macOS 常见数据位置为 `$HOME/Library/Application Support/rpcs3`，但移动过目录、设置了 VFS 或使用其他启动方式时须以实际目录为准。例如确认使用默认位置后，可写：

```sh
python3 ./install.py --game "/路径/GundamUC" --dlc "$HOME/Library/Application Support/rpcs3/dev_hdd0/game/BLJS10154" --check-only
```

不要给安装器加 `sudo` 来绕过版本或空间错误。外置盘必须已经挂载且可写；安装期间不要拔盘。

## 7. 更新过程中会发生什么

- `--check-only` 校验包内差分、游戏编号、源文件指纹和资源依赖，不写入游戏资源。
- 正式安装先保存回退副本，再在临时目录重建资源并校验，最后才替换游戏文件。
- 对已经是相同目标版本的资源会跳过；出现“无需重复安装”不代表失败。
- 本体和 DLC 分别位于不同目录，指定错误目录不会自动找到真正正在使用的那份游戏。
- 不包含在已核对范围内的升级覆盖文件会被拒绝，不直接覆盖 EBOOT。
- 大资源差分重建、读写和 SHA-256 校验可能需要等待。不要仅因进度暂时没变化就拔盘或结束进程。

## 8. 上一版无 BGM／对白的补救

已确认的一类问题是旧整合目录取自 ISO9660 的大写文件名，原始 UDF 音频路径实际为 `sound/.../*.fsb`。在区分大小写的环境里可能找不到资源。声音修复只规范文件及目录名，不替换或转码音频内容。

不要把整个游戏所有文件强制改成小写，也不要只改 `BGM.FSB` 一个名字。使用包内配套的音频路径工具，按其原始目录映射修复。

发行包中音频工具位于 `tools/audio-paths/`，Windows：

```powershell
py -3 .\tools\audio-paths\fix_audio_paths.py "D:\Games\GundamUC"
py -3 .\tools\audio-paths\fix_audio_paths.py "D:\Games\GundamUC" --apply
```

macOS / Linux：

```sh
python3 ./tools/audio-paths/fix_audio_paths.py "/路径/GundamUC"
python3 ./tools/audio-paths/fix_audio_paths.py "/路径/GundamUC" --apply
```

第一条只检查，第二条才重命名。工具实际位于包内 tools/audio-paths/。工具会检查重命名前后的音频 SHA-256，并生成回退记录。新版整合包应直接采用正确路径，不需要重复修复。

这只能解决已确认的路径问题；如果所有声音都没有，还应核对系统输出设备、模拟器音量和游戏声音设置。不要把其他设备的全部无声音问题都归因于大小写。

## 9. 新整合包用户怎样替换旧整合包

1. 先将新 ZIP 完整解压到新的独立目录，避免与旧 `Game` 混合覆盖。
2. 按包内校验脚本检查解压内容。新整合包已经应用汉化，不再重复打差分。
3. 备份旧的 `dev_hdd0/game/BLJS10154` 到模拟器游戏数据目录以外；保留整个目录，不只备份 EBOOT。
4. 按新整合包说明安装其匹配的升级／DLC 目录，确认最终层级正确。不要选“跳过全部同名文件”拼出新旧混合版。
5. 在模拟器中添加新版 `Game`，确认启动路径确实指向新版。
6. 使用原来的个人存档进行验证；不要用别人打包的用户目录覆盖自己的存档。
7. 确认运行无误后，再自行决定是否保留旧游戏副本；回退副本建议继续留存。

整合包中应明确写出实际游戏版本 **01.01**、汉化版本和所含 DLC 清单。不得只凭一个“完整版”文件名推断全部 DLC 均包含或均已解锁。

## 10. 如何确认更新成功

1. 安装器结束时没有报错，再次执行同一条 `--check-only` 应识别已安装目标资源。
2. 在 RPCS3 核对游戏编号和实际启动路径；测试时不要误开另一个旧副本。
3. 查看菜单、对白与字体，进入已知过场检查字幕显示时间。
4. 分别确认菜单 BGM、任务 BGM、角色对白和音效，不只验证其中一种。
5. 已有 DLC 用户确认相应任务或内容仍可访问；有些解锁条件受存档进度或个人授权影响。

文件校验通过表示文件内容与构建目标一致，不等于所有关卡或全部设备已完成实机测试。最终发布页应单独列出实际测试范围。

## 11. 回退方法

汉化安装器的备份位于本体目录下：

```text
GundamUC_CN_Backups/<本次安装编号>/restore.json
```

完全退出 RPCS3，使用含该 `restore.json` 的文件夹进行回退。

```powershell
py -3 .\install.py --restore "D:\Games\GundamUC\GundamUC_CN_Backups\本次安装编号"
```

```sh
python3 ./install.py --restore "/路径/GundamUC/GundamUC_CN_Backups/本次安装编号"
```

它恢复到**这次安装之前**：若从上一版汉化升级，则恢复上一版；不会自动恢复到最初原版，也不会卸载官方升级。

音频路径工具另有 `UC音频路径修复记录-*.json` 回退记录，使用该工具自己的 `--restore`：

```sh
python3 ./tools/audio-paths/fix_audio_paths.py --restore "/路径/UC音频路径修复记录-实际编号.json"
```

若已经恢复成正确路径，通常无需回退音频修复。回退会恢复之前的命名，原先的路径问题也可能随之返回。

恢复工具若检测到安装后资源又被其他补丁修改，会拒绝盲目覆盖。保留备份与错误信息，再排查；不要删除锁文件来强行开始新安装。

## 12. 常见错误如何处理

| 提示／现象 | 处理步骤 |
| --- | --- |
| 找不到 install.py | 先进入差分包解压目录；不要在整合版目录照抄差分命令 |
| Python 命令不存在 | 安装或定位 Python 3；不要把命令直接输入模拟器 |
| 游戏编号不匹配 | 核对是 BLJS10154，未选到别的高达游戏 |
| 原版资源或资源版本不受支持 | 核对上一版是否在支持清单中；保留现状，不要强行覆盖 |
| 1.01 升级数据不完整 | 核对真实游戏数据目录及对应升级文件；不要手改 PARAM.SFO |
| 存在未适配的覆盖资源 | 可能混装更新或第三方修改版；恢复匹配资源后重新检查 |
| DLC 任务资源不成对／缺少依赖 | 检查复制或安装是否完整，不要只拿单个 BHD/BDT 文件拼装 |
| 大小写冲突 | 同目录出现仅大小写不同的多个文件；先保留它们并反馈，不随机删一个 |
| 空间不足 | 根据安装器给出的实际空间需求腾出空间或换盘，不能只按 ZIP 大小估算 |
| 模拟器仍在运行 | 保存并完整退出 RPCS3，再安装 |
| 检测到未恢复的中断 | 按对应备份恢复，勿直接删除锁文件 |
| 字体仍旧或部分日文 | 核对本体启动路径、DLC 根目录及更新覆盖层是否对应同一套版本 |
| 只剩音效没有 BGM／对白 | 先核对音频路径工具检查结果，再核对原始音频是否完整 |
| 黑屏、报错或无法启动 | 保留日志，先按本次备份回退作对照；不要连续叠加未知补丁 |

## 13. 下载完整性与隐私

压缩包外的 `.sha256` 是下载完整性校验。Windows 可使用：

```powershell
Get-FileHash -Algorithm SHA256 "下载的实际文件名.zip"
```

macOS：

```sh
shasum -a 256 "下载的实际文件名.zip"
```

对照发布页或 `.sha256` 的完整 64 位值。哈希能核对文件是否一致，本身不能证明绝对没有恶意代码，也不能识别未知来源文件的作者身份。

本地安装／回退记录可能包含自己的目录路径，不要将它们原样公开上传。反馈可以提供发行版本、操作系统、模拟器版本、错误信息和具体页面；先遮盖用户名、账号、个人目录、授权文件及其他隐私。
